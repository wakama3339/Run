# runc v0.1 — компилятор: IR → COFF obj → Linker (PE .exe)

Самописный тулчейн без LLVM / `.s` / `.asm` / внешних ассемблеров и линкеров.
Машинный код x64 эмитится побайтово, `.obj` пишется вручную по спецу COFF,
`.exe` собирается собственным линкером (PE32+, только `kernel32.dll`).

## Архитектура (точка роста)

```
stdlib/builtins.rn ──┐
                     ├─> Lexer ─> Parser ─> AST ─> IR (ir.h) ─> Codegen ─> app.obj ─┐
examples/*.rn ───────┘                                          builtins.obj ──────┤
                                                                                   ├─> Linker ─> .exe
src/lexer.cpp ─────── токены                                   src/codegen.cpp ─────┘
src/parser.cpp ────── AST (fn, x: type, const, print, if/while/for, выражения)    src/x64.h ─────────── эмиттер байтов x64
src/ir.cpp ────────── Module/Function/Block/Instr + типы       src/coff.cpp ──────── запись COFF .obj
src/linker.cpp ────── склейка секций, REL32, импорт kernel32, PE
```

Минимум работает сейчас:

```rust
fn main() void:
    print("Hello World")
```

Типы вывода `print`: `str` `int` `float` `bool` `char`.

Переменные: `x: int = 42` (мутабельная), `const limit: int = 10` (только чтение).

## Выражения (v0.3)

Приоритет (от низкого): `||` → `&&` → `== !=` → `< <= > >=` → `+ -` →
`* /` → унарные `- !` → `**` (правоассоциитивен, выше унарных:
`-2**2 == -(2**2)`, показатель допускает минус: `2**-1`), скобки `()`.

- `+ - * /`: `int`/`int` → `int` (деление целочисленное), `float`/`float` → `float`.
- `%`: только `int` (остаток знакового деления: `-7 % 3` → `-1`); деление на
  ноль — аппаратное исключение, как в C.
- `**`: показатель всегда `int`; `int**int` → `int` (отр. показатель → 0),
  `float**int` → `float` (отр. показатель → `1/x`).
- `== !=`: все типы (для `str` — побайтовое сравнение); `< <= > >=`: только `int`/`float`.
- `! && ||`: только `bool` (выражения чистые, вычисление eager — эквивалентно
  short-circuit). Результат сравнений/логики — `bool`, печатается `true`/`false`.
- Деление int на ноль — аппаратное исключение (как в C); `NaN` в сравнениях —
  unordered-мусор (документировано, как и печать `NaN/Inf`).

## Функции (v0.6)

```rust
fn add(a: int, b: int) int:
    return a + b

fn fact(n: int) int:
    if n <= 1:
        return 1
    return n * fact(n - 1)

fn main() void:
    print(add(2, 3))
    print(fact(5))
```

- Параметры `name: type`, возврат `return expr` / голый `return` для `void`;
  вызовы — выражения (`print(add(1, 2))`, вложенные), `void`-вызовы — стейтменты.
- Порядок определений свободный, рекурсия работает (двухпроходный builder:
  сначала сигнатуры, потом тела). `main` обязан быть `fn main() void`.
- ABI вызовов runc64 (только пользователь↔пользователь): `int/bool/char`
  и половины `str` — по порядку в `RCX,RDX,R8,R9`, далее стек;
  `float` — в `XMM0–XMM3`, далее стек (зона `[RSP+32+8k]`, выравнивание кадра);
  возврат: `int` — `RAX`, `float` — `XMM0`, `str` — `RAX(ptr)+RDX(len)`.
  Аргументы вычисляются в слоты до `sub rsp`, moves — после (со сдвигом `+alloc`).
- Проверки: арность/типы аргументов, тип возврата, `return` из `void`,
  дубли функций/параметров, `main` без параметров.

## Модули и import (v0.7)

```rust
import "libmath.rn"
import "sub/helper.rn"
import "../shared.rn"

fn main() void:
    print(add(20, 22))
```

- Путь резолвится относительно импортирующего файла (`/`, `../`, подпапки;
  в строках только `/` — `\` в `.rn`-строках это escape).
- Каждый файл включается один раз (по каноническому пути) — diamond-импорты
  безопасны; циклы — ошибка с цепочкой (`a.rn -> b.rn -> a.rn`).
- Все функции сливаются в одну программу и линкуются по именам (порядок
  и `main` в любом файле); дубли — ошибка с файлом и строкой обоих определений.
- Все ошибки многофайловой сборки содержат `файл:строка`.
- `stdlib/builtins.rn` идёт через тот же загрузчик (неявный import для всех).
- Осознанно v0.7: слияние на уровне AST в один `app.obj`; честная раздельная
  компиляция (`.rn` → свой `.obj` → линкер связывает N объектов) — next step,
  линкер это уже умеет (так сейчас связываются `app.obj + builtins.obj`).

## Ветвления и циклы (v0.4–v0.5)

```rust
if x == 10:
    print("ten")
elif x > 10:
    print("big")
else:
    print("small")

while x < 20:
    x = x + 1

for i: int in 1..10:
    print(i)      // 1..9 (правая граница невключительно)
for j: int in 1..=3:
    print(j)      // 1..3 (включительно)
```

- Блоки — двоеточием + отступом (лексер выдаёт INDENT/DEDENT, как в Python;
  пустые и комментарийные строки на отступы не влияют, табы = 8).
  Тело также может быть одним стейтментом в той же строке: `if a: print(1)`.
- Условия `if/elif/while` строго `bool`. Цепочки `elif` (0+), необязательный
  `else`, вложенность без ограничений, пустые ветки разрешены.
- `for x: int in lo..hi:` / `lo..=hi:`: границы `int`, вычисляются один раз
  до цикла; шаг всегда +1; `x` объявляется (или переиспользуется `int`,
  но не `const`); пустой диапазон — ноль итераций.
- `break` / `continue` (v0.8): выход / следующая итерация внутреннего цикла;
  `continue` во `for` идёт через инкремент (иначе был бы вечный цикл).
- Lowering в IR: `while`/`for` desugar'ятся в те же `CondBr`/`Br` + блоки
  (`for` — через `Lt`/`Le` и `x = x + 1`), backend/линкер не менялись.
- Lowering в IR: `CondBr`/`Br` + блоки `then/elif/else/merge` (`--emit-ir` показывает).
  Переменные живут в стековых слотах кадра — phi-узлы не нужны.
- В кодогенерации ни один блок не проваливается в следующий: `Br`/`CondBr`
  прыгают явно, `Ret` прыгает на общую точку выхода с `ExitProcess`
  (иначе `merge` проваливался бы в `then` — бесконечный цикл, найдено отладкой).

## STDLIB

Папка `stdlib/`, в ней один STDLIB — `builtins` (`builtins.rn`).
Каждая программа компилируется вместе с ним: драйвер всегда подгружает
`stdlib/builtins.rn` («берёт в себя builtins»). Сейчас там только `print`
(как intrinsic: проверка типов во фронтенде → `IR::Print` → вызовы
`print_str/int/float/bool/char` из `builtins.obj`, который линкер клеит
с `app.obj`). Позже сюда лягут новые встроенные функции без смены архитектуры.

## Сборка

```bat
cmake -S . -B build -G Ninja
cmake --build build
```

## Использование

```bat
build\runc.exe examples\hello.rn -o hello.exe
hello.exe
build\runc.exe examples\alltypes.rn -o alltypes.exe --emit-ir -v
```

Проверено (Windows 11 x64, MinGW g++ 15.2): `hello.rn`, `alltypes.rn`,
`edge.rn`, `expr.rn` (30 комбинаций побайтово), `cond.rn`, `for.rn`
(сумма 1..=10 = 55), `funcs.rn` (рекурсия `fact(5)` = 120, 7 mixed-аргументов,
`str`-return, вложенные вызовы), `useimport.rn` (`import` + `../` + diamond).
Ошибки типов/арности/отступов/импортов — с файлом, номером строки,
кодом выхода 1.

Флаги: `-o out.exe`, `--emit-ir` (дамп IR), `--keep-objs/--drop-objs`, `-v`.

Рядом с результатом остаются `*.app.obj` и `builtins.obj` — артефакты стадий
IR→obj→link, их можно рассматривать.

## Реализация print (backend, src/codegen.cpp)

- `__write_stdout(ptr,len)`: `GetStdHandle(-11)` + `WriteFile`, кадр 56 байт.
- `print_str`: `WriteFile` + `"\r\n"`.
- `print_int`: знаковый i64 → десятичная строка, делением на 10 назад по буферу.
- `print_float`: знак + целая часть (`cvttsd2si`) + 6 дробных цифр (`cvtsi2sd`,
  `subsd`, `mulsd 1e6`), фиксированный формат `[-]d+.dddddd`.
- `print_bool`: `true`/`false` + newline. `print_char`: 1 байт + newline.
- Вызовы внутри/между объектами — `E8 rel32`, импорты — `FF 15 [rip+__imp_*]`,
  строки/константы — `lea/movsd [rip+...]`; всё через REL32-релокации COFF.

## Ограничения v0.8 (намеренно, для развития)

- Нет пользовательских типов/массивов/структур (только `str/int/float/bool/char`).
- Шаг `for` всегда +1; нет `for` по строкам/коллекциям.
- `float`: фиксированные 6 знаков, без экспоненты; `NaN/Inf` — мусор.
- `str + str` — ошибка (добавить конкатенацию в builtins).
- Деление/`%` int на ноль — аппаратное исключение.
- Падение с конца не-`void` функции без `return` — мусор в регистре возврата.
- Импорты только `kernel32: GetStdHandle/WriteFile/ExitProcess`.
- Модули сливаются в один `app.obj` (раздельная компиляция — next step).

## Ловушка линкера (зафиксировано отладкой)

Лоадер Windows 10/11 отвергает образ с `MajorSubsystemVersion = 0`
(`CreateProcess` → `ERROR_BAD_EXE_FORMAT 193`), хотя парсеры вроде objdump
считают его валидным. Лечится `MajorSubsystemVersion = 6` (см. `linker.cpp`).
Диагностика: эталонный PE на Python + матрица in-place патчей полей —
так и нашли за один вечер вместо гадания.
